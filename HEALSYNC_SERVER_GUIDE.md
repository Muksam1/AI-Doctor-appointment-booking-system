# HealSync: Server Architecture Guide

This documentation provides an overview of the server-side architecture of the **HealSync: AI Doctor Appointment Booking System**. It explains the purpose of each folder and the critical role of environment configuration.

---

## 🏗️ Folder Structure Breakdown

| Folder | Purpose | Key Responsibilities |
| :--- | :--- | :--- |
| **`controllers/`** | **Business Logic** | Contains the actual functions that process requests. For example, `paymentController.js` handles the logic for initiating and verifying eSewa/Khalti payments. |
| **`models/`** | **Data Blueprints** | Defines the structure (Schema) of your database collections. `User.js`, `Doctor.js`, and `Appointment.js` ensure that data is stored consistently in MongoDB. |
| **`routes/`** | **API Entry Points** | Maps URL endpoints (e.g., `/api/payments/verify`) to their respective controller functions. It acts as the "receptionist" of your server. |
| **`middleware/`** | **Security & Filters** | Functions that run before your controllers. `authMiddleware.js` checks if a user is logged in (via JWT tokens) before allowing them to access protected pages. |
| **`config/`** | **System Settings** | Contains configuration files, primarily for connecting to the MongoDB database and setting up global environment defaults. |
| **`utils/`** | **Helper Tools** | Small, reusable functions used across the server. This includes OTP generators, email templates, and signature calculation for payment gateways. |

## 📁 Key Files in Root

### `index.js`
This is the **entry point** of your application. When you run `npm start`, this file executes. It:
- Initializes the Express server.
- Connects to the MongoDB database.
- Sets up Socket.io for real-time notifications.
- Loads all the routes and middleware.

### `.env` (The Secret Safe)
The `.env` file is the most sensitive part of your project. It stores **Secrets** and **Private Data** that should **NEVER** be shared or uploaded to GitHub.
- **Why is it needed?** It keeps your database passwords, API keys (for eSewa, SMS, etc.), and JWT secrets hidden from unauthorized eyes.
- **Admin Details:** If you see admin passwords or initial credentials here, they are used for the first-time setup of the system.
- **Security Rule:** This file is listed in `.gitignore` so it stays only on your local computer.

## 🚀 Key Features Implemented

1. **AI-Ready Architecture:** Designed to integrate with symptom analysis and doctor matching logic.
2. **Secure Payment Gateways:** Integration with **eSewa (v2)** and **Khalti** for seamless healthcare transactions.
3. **Real-time Notifications:** Uses WebSockets (Socket.io) to alert users immediately when an appointment is booked or approved.
4. **Role-Based Access Control (RBAC):** Distinct permissions for Patients, Doctors, and Admin to ensure data privacy.
5. **Robust Database Migrations:** Includes script utilities for cleaning up data and seeding test environments.
